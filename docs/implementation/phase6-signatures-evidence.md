# Phase 6 — Signatures and Evidence

Phase 6 adds the active-v5 signature and document boundary without reviving legacy `egas_*`, `activeRole`, delegation, deputy, `StageTask`, or historical repository authorization code.

Official sign-and-advance is available only at P1, P2, P4, S1, S2, and S3. The server locks the current execution and requires the current effective manager of its responsible operational unit; ADMIN accounts and work-assigned subordinates cannot sign. P4 and S3 resolve AUTH through the request routing unit's AUTH operational unit.

`POST /api/signatures/my-signature` accepts route-scoped raw PNG/JPEG bytes. Sharp validates and canonicalizes to private PNG storage; SHA-256, size, MIME type and opaque storage key are stored in `user_signature_asset`. Assets are versioned and may be deactivated. Deactivation prevents new signatures but does not invalidate historical signoffs; historical image/PDF use verifies the stored signoff checksum.

`POST /api/workflow/stages/:stageExecutionId/sign-and-advance` accepts exactly a raw password, active owned signature asset UUID, and optional one-signoff-only title override. The password is not trimmed, stored, logged, audited, snapshotted, or rendered. Reauthentication uses the current local authentication provider/password hash. A rejected password commits only `SIGNATURE_PASSWORD_REJECTED` security evidence and then returns `SIGNATURE_PASSWORD_INVALID`; no workflow mutation occurs.

Successful signing freezes a deterministic `stage_submission_snapshot`, inserts the immutable one-per-execution `workflow_signoff` and server-derived signer snapshot, completes the execution, and opens the resolved next execution in one transaction. P4 reuses the Promotion readiness/destination helper; S2 and S3 reuse the Secondment readiness helpers. Returns create new executions, so later signoffs supersede only for the current iteration while earlier evidence remains intact.

P5/S5 remain non-signing HR manager completion stages. They require the authoritative current-iteration signoffs and create one hashed `final_form_snapshot` before completion. Final evidence derives signed P4/S3 stage snapshots rather than mutable decision/selection rows. Promotion uses `EGAS-OFFICIAL-PROMOTION-AR-3.0` and freezes personnel/name, qualification and date, current job and start date, workbook-authoritative experience year/month/day triplet and reference date, performance/report, department, recommendation, nominated job and AUTH notes. The workbook explicitly supplies its experience duration triplet and reference date, so Phase 6 freezes those approved form values rather than recalculating them. Promotion continues to fail closed with `PROMOTION_DEPARTMENT_REQUIRED` because the approved workbook has no department/general-administration source. Secondment freezes candidate/current job, qualification/date, last report, selected position, organizational dependency and frozen qualification code/display name. It uses internal technical identifier `EGAS-OFFICIAL-SECONDMENT-AR-BASELINE-1.0`; it is not a stakeholder-approved V3 identifier.

Document APIs provide authorized current preview, final official PDF, and chronological audit PDF. Current previews are dynamic and never create frozen evidence; final PDFs render from only the immutable final snapshot, verify referenced signature and stored-PDF hashes, are retry-safe after post-commit failures, and never reopen or modify completed workflow evidence. `PdfService.ensureFinalPdfMaterialized` is the sole final-PDF materialization path for both lazy GET and post-completion best effort: it verifies snapshot/file hashes, uses bounded rendering, registers one winner through the unique database invariant, and removes only its own losing/failed contender file. Rendering is bounded by concurrent/queued/timeout/output-size limits. The audit PDF chronologically aggregates iteration and execution lifecycle, assignment, stage action, notes, snapshot hashes, signoffs and audit events without passwords, secrets or storage paths. Migration 004 adds the sole `frozen_pdf_document(final_form_snapshot_id)` at-most-one uniqueness invariant. Arabic visual QA and the approved source for Promotion department/general-administration remain unresolved external gaps.
